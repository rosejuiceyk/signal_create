# CAEN DT5800 硬件在环（HIL）集成方案

> 定位：Tier 2 —— 在**无反应堆**的条件下，用**已知真值**把"探测器 + 电子学 + 采集 + 分析"整条链在**真实硬件**上验通。
> 关键认知：DT5800 是 CAEN 的**数字探测器仿真器（Digital Detector Emulator）**，官方定位是"蒙特卡洛方法的硬件实现"。它本质上是你软件孪生的**硬件孪生**。

---

## 1. DT5800 能力速览（以官方手册/软件为准，下列为设计依据）

- **三种模式**：
  - *Pulser Mode*：用户定义幅度与速率的脉冲，支持恒定或泊松。
  - *Emulation Mode*：可编程能谱 + 时间分布 + 脉冲形状 + 噪声 + 基线漂移，**实时合成连续脉冲流**（它自己按分布随机抽，不是你的精确事件表）。
  - *Waveform Generator Mode*：任意波形，**每通道 1M 点 RAM**；可从数字脉冲处理器/数字化仪/示波器**导入形状与能谱文件**。
- **DT5800D 双通道**：支持**通道间事件关联**（含时间关联、共享能谱、master/slave 触发）——直接对应双探测器方法。
- 输出：最高 2 V（高阻 4 V）；最高 10 Mcps（泊松模式 5 Mcps）；序列可复现（存 kernel）或每次随机；USB 2.0；Windows 软件。
- 已知真实用例：ITER 径向中子相机用 DT5800D 验证脉冲处理（双通道不同衰减时间 + 不同能谱，比对已知输入 vs 算法输出）；VMM3a/sTGC 用其注入自定义形状 + 自定义幅度分布 + 指数时间波形（受堆积内存限制，达率有上限）。

### 1.1 必须先探测的能力（不同单元/固件可能不同）
1. 是否支持加载用户自定义的 **(energy, time-of-occurrence) 事件序列**（决定能否注入你的精确相关序列；DT5810 有 4 kpoints 该模式，DT5800 需确认）。
2. 任意波形模式的**最长可载点数**与是否支持**分段/循环播放**。
3. 堆积内存深度（决定给定脉冲形状下的**最高可达率**）。
4. DT5800D 事件关联的**可控参数**（时间关联步长、共享比例、master/slave）。
5. 导出/导入的**文件格式**（形状文件、能谱文件、波形文件的列定义与单位）。

> **设计原则**：不把方案押在任何单一能力上。下面按"必成 / 高价值但能力依赖"分档，档1、档2 无论如何都能做。

## 2. 三档使用方案

### 档 1 —— 电子学链 + 脉冲模型验证（🔴 必成）

**做什么**：用 DT5800（Emulation 或 Waveform 模式）以你的**双指数脉冲形状 + He-3 能谱 + 噪声 + 基线漂移**生成信号 → 经你将用于反应堆的**同一采集链**采集 → 与软件孪生在**相同设定**下的输出比对边缘统计。

**比什么**（软件孪生 vs DT5800 经真实 DAQ）：
- 平均脉冲形状、`tau_r/tau_d`、上升/下降/电荷分布；
- 脉冲高度谱（PHS）；
- 噪声底与基线漂移特性；
- ADC 量化、饱和/裁剪行为。

**价值**：给孪生的"探测器 + 电子学"层一个**硬件真值**。若软件孪生能复现 DT5800 经真实 DAQ 的这些统计，则孪生的前端建模可信。

### 档 2 —— 死时间 / 堆积标定（🔴 必成）

**做什么**：固定形状，**扫描 DT5800 计数率**（低→高，直到明显堆积）→ 观测真实 DAQ + 你的触发/事件匹配/死时间流水线的行为。

**比什么**：
- 实测死时间类型与量值 vs 孪生死时间模型；
- 计数损失曲线、堆积概率 vs 率；
- 用 DT5800 已知输入率**校准孪生的死时间/堆积参数**，把校准结果喂回 Phase B 的死时间研究。

**价值**：Phase B 里"脉冲计数法可用上限"这条曲线，从此有**真实电子学**背书，而不仅是软件假设。

### 档 3 —— 双探测器互协方差 + 相关序列注入（🟡 高价值，能力依赖）

**3a. 双探测器互协方差验证（DT5800D 关联功能，通常可做）**
- 用 DT5800D 双通道输出一对**带已知关联**的信号（利用其时间关联/共享能谱/master-slave）。
- 用它验证 Phase C 的 **CCF/CTM 估计器**能否正确提取"已知注入的关联"，并验证**两通道时间同步**处理正确。
- 注意：DT5800 的关联是 CAEN 自己的机制（面向符合/PSD 测试），不必是"裂变链式"关联；但它是一个**已知的、可控的**关联，足以验证互协方差数学本身是否正确——这本身就有价值。

**3b. 注入 Phase A 的精确相关序列（若单元支持序列/任意波形足够深度）**
- 若支持 (energy,time) 序列或足够长的任意波形：把 **Phase A 生成的相关探测事件序列**导成 DT5800 可载格式 → 硬件播放 → 真实 DAQ 采集 → 跑 Phase B/C 反演。
- 这实现**真实电子学上的端到端已知-α 验证**：输入是你设定的已知 α 的相关序列，看反演能否在真实死时间/噪声下复原。
- **约束**：任意波形 1M 点/通道 ≈ 4–10 ms@100–250 MS/s；长记录需分段或循环（循环会在周期处引入伪关联，分析时排除该滞后）。序列模式深度不足时，退回用**短段验证 prompt 关联**（1/α ~ 0.1–10 ms，短段可捕捉 prompt 项但统计有限）。

## 3. 软件侧要 Codex 建的工具（Phase HIL 的编码内容）

> 全部**厂商无关、profile 驱动**，且**可用合成 fixture 开发与测试**，不接实体设备也能通过 CI。

1. **导出器 `io/dt5800_export.py`**：
   - 把孪生的事件表/波形导成 DT5800 可载的**形状文件 / 能谱文件 / (energy,time) 序列 / 任意波形**（按探测到的能力选格式）。
   - 单位、采样率、量程、极性显式配置，不硬编码。
2. **导入器（复用/扩展 `io/oscilloscope.py` 与 `io/dt5800_stub.py`）**：
   - 按 profile 解析采集回来的波形（列名/单位/采样率不硬编码）；无法判定单位时**报错而非猜测**。
   - 复用 `EXPERIMENT_DATA_COLLECTION.md` 的 `run_meta` schema。
3. **比对器 `analysis/hil_compare.py`**：
   - 对齐"软件孪生 vs DT5800-经-DAQ"的边缘统计（脉冲形状、PHS、噪声、死时间曲线），输出差异指标 + QC 状态 + Markdown/HTML 报告。
   - 明确区分 `measured`（DT5800 经真实 DAQ）、`simulated`（软件孪生）、`derived`。
4. **合成 fixture**：
   - 用软件孪生生成"假的 DT5800 输出"作为 fixture，驱动导入器+比对器的全部单测，保证无硬件也能跑 CI。
   - 真实设备接入时，只需把 fixture 换成实测文件，流水线不变。

## 4. 与反应堆实验的衔接（为什么这一步先做）

在去反应堆之前，用 DT5800 把整条链（探测器脉冲模型 → 电子学 → 采集 → 触发/死时间 → 噪声反演）在**已知真值**下验通。之后：
- 反应堆 run 用**同一条链**采集（见采集规范 §5 的 DT5800 交叉参照）；
- 反应堆数据的电子学/采集部分已被 DT5800 背书；
- 于是真实数据里 Phase C 的偏差可**干净归因于"真实裂变链物理"**，而非采集链伪迹。

这就是三级阶梯里 Tier 2 → Tier 3 的承接逻辑：**先消除电子学不确定性，再面对物理不确定性。**

---

## 5. 验收标准（Phase HIL）

1. 导出器能产出 DT5800 可载文件（对至少一种探测到的能力路径），单位/采样率/极性正确、可回读自检。
2. 导入器能按 ≥2 种 profile 正确解析波形；单位不明确时报错；复用 run_meta schema。
3. 比对器在**合成 fixture** 上：当"假 DT5800 输出"= 软件孪生同参数输出时，差异指标应在容限内（自洽）；当人为注入偏差时，能被检出并标 QC。
4. 死时间标定流程能从"已知输入率序列"反出死时间/堆积参数，与设定一致（合成 fixture 验证）。
5. 双探测器互协方差在"已知注入关联"的合成 fixture 上被正确提取。
6. 报告明确区分 measured/simulated/derived；全量 ruff/mypy/pytest 绿灯。
7. 文档说明本单元实际探测到的能力档位，以及档3是否可用及其约束。

---

## 6. 明确不做（Phase HIL）

- 不实现对 DT5800 的实时硬件控制/驱动（本阶段只做文件级导出/导入/比对；实时控制留后续）。
- 不声称任何未经实测确认的 DT5800 能力；能力探测结果写进文档。
- 不把 DT5800 的 Emulation 模式随机序列当作"精确事件表"（它是自身随机抽样）。
- 不接入反应堆真实数据（那是后续数据接入阶段）。
