# 阶段可视化验证规格（VALIDATION_VISUALIZATIONS）

> 目的：把每个 phase 的验收从"一堆数字阈值"升级为**一眼可判的图 + 可选交互仪表盘**。
> 核心认知：在中子噪声这个领域，**图本身就是物理**——Feynman 曲线、Rossi 直方图、事件簇、去卷积前后，每张图都让"对不对"自证。数字阈值仍保留（CI 硬门禁），但图是给人看的主界面。
> 本文可整体并入 Codex 开发包，作为对各阶段"必须实现"的可视化补充。

---

## 0. 两层交付（推荐）

- **第一层（主，CI 门禁）：静态验证报告**。每个阶段自动生成一组 PNG/HTML 图，落到 `outputs/phaseX_report/`，作为人工审核的主产物。版本可控、可回归、与既有"每阶段出报告等人工审核"的门禁完全一致。**这是必做项。**
- **第二层（可选，探索/答辩）：交互验证仪表盘**。一个网页界面，用滑块改参数（k_eff、α、计数率、NSR、γ…）→ 实时重算重绘。适合探索与竞赛现场演示。

> **关键架构约束（避免重蹈旧 Web 应用覆辙）**：把画图做成 `analysis/figures.py` 里的**可复用纯函数**（输入数据/拟合结果，输出 Figure）。静态报告的 CLI 命令调它们、可选仪表盘也调它们——**逻辑只有一份，两处复用**。旧 Streamlit 应用的问题是逻辑埋在 UI 里；这次逻辑在 analysis 层、可单测，UI 只是薄壳。

## 1. 每阶段推荐图（含"证明了什么"）

> 已渲染的示例见随附 `validation_figures_gallery.pdf`（fig1–fig4）。标 ★ 的是该阶段的"钱图"（最该进论文/海报/答辩）。

### Phase A —— 相关中子生成器（"事件变相关了"要肉眼可见）
| 图 | 证明 |
|---|---|
| ★ 事件 raster（泊松 vs 相关，同率并排） | 相关序列出现可见的裂变链簇；泊松均匀。最直观的"aha" |
| ★ 间隔分布（log-y，叠加解析指数） | 泊松是直线；相关在短滞后有超出 = 关联 |
| ★ Fano 因子 vs 门宽 | 泊松恒 =1；相关 >1 且随门宽上升 = 超泊松 |
| 平均率 vs k_eff（叠加 S·ε/(1−k) 解析曲线） | 一阶正确性，点落在解析线上 |
| 裂变链树（单个源中子的分支，标出探测） | 分支过程的直接可视化，极具教学/展示价值 |
| 退化演示（k→0 时相关间隔分布塌回泊松指数） | 退化极限的可视化证明 |

### Phase B —— 噪声分析 + α 复原（拟合即验收）
| 图 | 证明 |
|---|---|
| Rossi-α 时间差直方图 + 指数拟合 | 提取 α；关联项 A 与偶然平台 B 分离 |
| Feynman-α Y(T) 曲线 + 拟合 | Y 上升并饱和到 Y∞；曲线形状即物理 |
| PSD + 洛伦兹拟合（拐点 α/2π） | 频域独立给出 α |
| ★ **α 复原 parity 图**（α_hat vs α_true，三方法，带 ±5% 带与误差棒） | 把"|α_hat−α_true|/α_true<5%"变成一眼可读的散点对角线——**整条主线的验证图** |
| 三方法一致性（Rossi/Feynman/PSD 并排或散点） | 交叉验证一致 |
| 死时间偏置曲线（α_hat/α_true vs 真率，Hazama 修正前后） | 脉冲计数可用上限的可视化 |
| bootstrap α 分布 vs 朴素误差棒 | 为什么朴素最小二乘低估不确定度 |

### Phase HIL —— DT5800 硬件在环（软件孪生 vs 硬件经真实 DAQ）
| 图 | 证明 |
|---|---|
| ★ 平均脉冲形状叠加（孪生 vs 硬件）+ 残差内插 | 前端脉冲模型与真实硬件一致 |
| 脉冲高度谱叠加（孪生 vs 实测） | 能谱模型一致（764 keV 峰对齐） |
| ★ 死时间/计数损失曲线（观测率 vs 真率，孪生 vs 硬件，含理想线） | 死时间模型被真实电子学背书 |
| 噪声 PSD/基线叠加（含 DAQ 频率传递伪迹检查） | 噪声模型一致；捕捉 V 形带阻等采集链伪迹 |
| 双探测器 CCF：注入的已知关联 vs 复原 | 互协方差估计器在硬件上正确 |
| QC 交通灯表（measured/simulated/derived 差异 + 通过标记） | 一屏看清所有比对项状态 |

### Phase C —— 连续信号噪声分析（He-3 前沿）
| 图 | 证明 |
|---|---|
| ★ 去卷积前后（原始连续信号 → 近 Dirac 串） | 去卷积有效，最直观（对标 Boros Fig.2） |

## 2. 交互仪表盘设计（第二层，可选）

**定位调整**：此前把旧 Streamlit 应用（Phase 3.5）归档，因为它只是个无科学价值的信号生成 UI。**验证仪表盘不同**——它是交互式探索噪声物理的工具，对竞赛现场演示价值很高。因此**为这个新目的复活一个网页界面是合理的**，且与旧应用完全不同。

- **技术**：复用归档的 Streamlit 骨架（或轻量替代），但只作为 `analysis/figures.py` 的薄壳。
- **页面（按阶段分 tab）**：
  - Phase A tab：滑块 k_eff / α / ε / 计数率 → 实时刷新 raster / 间隔分布 / Fano。
  - Phase B tab：同参数 → 实时 Rossi/Feynman/PSD 拟合 + 当前 α_hat vs α_true。
  - Phase HIL tab：上传/选择实测或 fixture 文件 → 与孪生同参数比对图 + QC 灯。
  - Phase C tab：滑块 NSR / γ → 实时去卷积前后 + 稳定域中的当前点 + 可用边界上的当前工况。
- **原则**：仪表盘不做任何独立计算逻辑；所有图来自 analysis 层同一批函数；仅本地 `127.0.0.1` 绑定（承旧应用的安全约束）。
- **价值排序**：静态报告是刚需（CI 门禁 + 论文图）；仪表盘是加分（探索 + 演示）。**先做静态报告，仪表盘视精力再上。**

## 3. 如何并入 Codex 开发包

对每个阶段的"必须实现"追加一条**可视化产物**要求，并新增一个可复用图库模块。建议改动：

1. 新增 `src/he3sim/analysis/figures.py`：本文件 §1 各图的纯函数（输入数据/拟合，输出 matplotlib Figure），全部可单测（例如"拟合从数据提取的 α 在容限内"作为测试，图只是其可视化）。
2. 每个阶段的 CLI 报告命令生成对应 PNG/HTML 到 `outputs/phaseX_report/`，并在阶段验收清单里加"报告图已生成且关键拟合值标注正确"。
3. （可选）新增 `he3sim dashboard` 薄壳命令启动交互仪表盘，复用 `figures.py`。
4. 在各 `docs/phases/phase_*.md` 的"必须实现"末尾加一行："生成本阶段验证报告图（见 `VALIDATION_VISUALIZATIONS.md` §1 对应条目），关键量（α、Y∞、拐点、差异指标）在图上标注。"

### 可直接发送给 Codex 的追加提示词（在某阶段实施时附带）

```text
除本阶段既有必做项外，追加可视化验收：
1. 在 analysis/figures.py 中实现本阶段对应的图函数（见 @VALIDATION_VISUALIZATIONS.md §1），函数是纯函数：输入数据/拟合结果，输出 matplotlib Figure，可单测。
2. 本阶段 CLI 报告命令自动生成这些图（PNG+HTML）到 outputs/ 下，关键拟合量（如 α、Y∞、拐点频率、差异指标）在图上清晰标注。
3. 为图函数加数据级单测（例如从数据反出的 α 在容限内），图只作为可视化，不含独立计算逻辑。
不要在本阶段实现交互仪表盘（那是可选的独立薄壳，待单独授权）。
```

---

## 4. 一句话建议

**静态验证报告设为每阶段的硬门禁（必做，也是论文图来源）；交互仪表盘作为复活的、面向验证与演示的网页薄壳（可选，竞赛加分）。两者共用 `analysis/figures.py` 一套函数，逻辑只有一份。**
